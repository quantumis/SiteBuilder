# Site Builder — руководство пользователя

**Плагин Site Builder** — инструмент для быстрого разворачивания WordPress-сайтов из подготовленных архивов контента (FSR-архивов) с автоматической генерацией темы, меню, страниц и SEO-разметки.

Документ рассчитан на **разработчиков сайтов** — тех, кто наполняет и сдаёт сайты, а не кодеров плагина. Для расширения плагина (создание новых вариаций темы) смотри отдельный документ `DEVELOPER_SPECIFICATION.md`.

## 1. Установка и первый запуск

### Требования

- WordPress 5.6+
- PHP 7.4+
- Права `manage_options` (администратор сайта)
- MySQL/MariaDB с поддержкой транзакций (для отката импорта)

### Установка

1. Скачай архив `site-builder.zip`
2. WordPress-админка → **Плагины → Добавить новый → Загрузить плагин**
3. Выбери ZIP, нажми «Установить», затем «Активировать»
4. В левом меню админки появится пункт **Site Builder**

### Первый запуск

При активации плагин **автоматически**:
- Создаёт 2 пункта меню (`Main Auto Menu` и `Footer Auto Menu`) и привязывает их к локациям `primary` / `footer`
- Создаёт страницу **«Все статьи»** с шаблоном articles-grid
- Создаёт страницу **«Sitemap»** с шаблоном sitemap
- Регистрирует media-обработчик для картинок из FSR-архивов
- Резервирует опции в базе данных (см. раздел 15 если нужно очистить)

**После активации** первым делом:
1. Иди в **Site Builder → Тема** — выбери шапку, подвал, цветовую схему → «Сгенерировать и активировать тему»
2. Только после этого запускай **FSR Import** — иначе импорт пройдёт, но контент будет отображаться в дефолтной теме WordPress (не так как задумано)

## 2. Обзор интерфейса

Плагин показывает 8 вкладок в **Site Builder** боковом меню:

| Вкладка | Что делает | Когда использовать |
|---|---|---|
| **FSR Import** | Основной импорт полного архива | Разворачивание нового сайта из FSR-архива |
| **Тема** | Конструктор темы (header + footer + style) | Первый шаг перед импортом, или при смене дизайна |
| **Создание сайта** | Legacy импорт (устаревший, MJ-архивы) | Только для старых архивов без FSR-структуры |
| **Добавление страниц** | Legacy добавление отдельных страниц | Только для старых архивов |
| **MD Restore** | Восстановление контента из бэкапа `.md` | Если нужно откатить редакторские правки |
| **Отчёт** | Журнал импортов с ошибками и warnings | После импорта — проверить что попало в журнал |
| **Откат** | Полный откат импорта (удаление всего что импортировано) | Если импорт пошёл не так или нужно начать заново |
| **Настройки** | Размер batch'а, шаблоны страниц | Разовая настройка производительности |

### Порядок работы для нового сайта

```
1. Тема         → выбрать header + footer + style, сгенерировать
2. Настройки    → (опционально) размер batch'а если сервер слабый
3. FSR Import   → выбрать архив → маппинг полей → запустить
4. Отчёт        → проверить что нет ошибок
5. Ручные правки → лого, favicon, доп. настройки WP
```

## 3. Формат FSR-архива

FSR — **File System Representation**. Это папка (или ZIP-архив), где **каждая папка внутри соответствует одной странице сайта**. Иерархия папок отражает иерархию страниц.

### Пример структуры

```
BET-S1-ES-PILLAR-golf-apuestas/
├── index.md                      ← корневая страница (автоматически становится главной сайта)
├── images/
│   └── hero.jpg
├── noticias [1M;Noticias][A]/    ← подкатегория "Новости" в главном меню, articles-grid
│   ├── index.md
│   ├── nuevo-torneo-2026/
│   │   ├── index.md
│   │   └── images/
│   │       └── cover.jpg
│   └── premiacion-2025 [DLY]/    ← отложенная публикация
│       └── index.md
├── estadisticas [2M;Estadísticas]/  ← пункт меню
│   ├── index.md
│   ├── mejores-golfistas/
│   │   └── index.md
│   └── comparativas/
│       └── index.md
├── privacidad [U][1F;Privacidad]/  ← utility + footer menu
│   └── index.md
└── cookies [U][2F;Cookies]/
    └── index.md
```

### Правила формата

1. **Одна папка = одна страница**. Название папки становится slug'ом URL.
2. **Каждая папка должна содержать `index.md` или `index.html`** — это контент страницы.
3. **Иерархия папок = иерархия страниц**. Вложенная папка становится дочерней страницей в WordPress.
4. **Изображения** — в подпапке `images/` рядом с `index.md` (не обязательно, но принято).
5. **Флаги** в квадратных скобках после имени папки — задают поведение (см. следующий раздел).

### Что делает плагин при импорте

1. Проходит папку рекурсивно (в глубину, алфавитный порядок)
2. Собирает **очередь задач** — по одной на каждую папку с `index.md`
3. Ставит порядковый номер `dly_seq` каждой DLY-странице (для расчёта расписания публикации)
4. Обрабатывает задачи батчами (по умолчанию — 15 страниц за AJAX-запрос)
5. Для каждой страницы:
   - Читает `index.md`
   - Парсит frontmatter (метаданные)
   - Обрабатывает блоки, шорткоды, ссылки
   - Загружает изображения в медиатеку WP
   - Создаёт страницу в WP с правильным parent'ом
   - Заполняет meta-поля для SEO
   - Добавляет в меню если флаг `[M]` или `[F]`
6. Сохраняет журнал результатов для просмотра во вкладке **Отчёт**

## 4. Флаги в именах папок

Флаги — это `[XXX]` конструкции после имени папки. Их можно **комбинировать** — сколько угодно на одну папку.

### Меню

**`[M]` или `[<order>M<depth>;<label>]`** — добавить в главное меню.

- `M` — просто добавить в конец
- `1M` — добавить как 1-й пункт
- `M3` — добавить с глубиной подменю 3 уровня
- `2M;Статистика` — 2-й пункт с меткой «Статистика» (иначе берётся из title страницы)
- `1M3;Главная` — всё вместе: 1-й, 3 уровня, метка

Примеры:
```
о-нас [1M;О нас]/             ← 1-й пункт главного меню, метка "О нас"
контакты [3M]/                ← 3-й пункт, метка = title страницы
статьи [2M2;Все статьи][A]/   ← 2-й пункт, глубина 2, метка "Все статьи", + articles-grid
```

### Footer-меню

**`[F]` или `[<order>F;<label>]`** — добавить в футер-меню.

- `F` — просто добавить в конец
- `1F` — как 1-й пункт
- `2F;О проекте` — 2-й пункт с меткой «О проекте»

Примеры:
```
о-проекте [1F;О проекте]/     ← 1-й пункт футер-меню
privacidad [U][1F;Privacidad]/ ← utility + 1-й пункт футер-меню
```

### Специальные назначения (одиночные буквы)

| Флаг | Что делает |
|---|---|
| **`[U]`** | Utility-страница (privacy, cookies, legal). Не попадает в основные списки, но доступна |
| **`[A]`** | Articles grid — страница показывает сетку из 12 карточек статей (с пагинацией `?gp=N`) |
| **`[W]`** | Метка «Страница О нас». Модификатор для `[U]` — точно идентифицирует About Us. Обычно ставится **вместе с `[U]`**. Главной сайта эта страница не становится — главную WordPress определяет по корневой папке архива автоматически |
| **`[N]`** | News-page (для интеграции с news-broker плагином — категория `news`) |
| **`[E]`** | Events-page (для интеграции с matches-broker плагином — категория `event`) |

### DLY — отложенная публикация

**`[DLY]`** — публиковать по расписанию (см. раздел 11).

**`[DLY=YYYY-MM-DD]`** — публиковать в конкретный день (время рандомизируется в диапазоне 9:00–22:00).

Примеры:
```
premiacion-2025 [DLY]/         ← в очередь на распределение по расписанию
top-tournoi [DLY=2026-08-15]/  ← ровно 15 августа 2026 (с рандомным временем дня)
```

### Комбинирование флагов

Флаги можно комбинировать — они не конфликтуют:

```
о-нас [U][W][1F;О нас]/
```

Означает:
- `[U]` — utility-страница (не попадает в основные списки статей)
- `[W]` — метка «Страница О нас» (для идентификации типа страницы)
- `[1F;О нас]` — 1-й пункт футер-меню с меткой «О нас»

### Что делает плагин с неизвестными флагами

Если написать `[SOMETHING]` которого плагин не знает — в **журнал импорта** попадёт warning с указанием файла. Флаг игнорируется, папка обрабатывается как обычная страница.

## 5. Формат `index.md` — frontmatter и контент

### Структура файла

```markdown
---
title: Заголовок страницы
description: SEO-описание для поисковиков (150–160 символов)
headline: Социальный заголовок (для Open Graph и Twitter Cards)
headimg: images/hero.jpg
---

# Заголовок статьи (может совпадать с title или отличаться)

Обычный markdown-контент. Плагин поддерживает:
- **Жирный текст** и *курсив*
- [Ссылки](/relative/path/)
- Изображения ![alt](images/photo.jpg)
- Списки, таблицы, цитаты, инлайн-код
- H2, H3, H4 заголовки
- Специальные блоки (см. раздел 7)
- Шорткоды (см. раздел 6)
```

### YAML-frontmatter — метаданные

Frontmatter — блок между двумя `---` в самом начале файла. **Опциональный**, но крайне желательный для SEO.

| Поле | Что это | Куда попадает |
|---|---|---|
| `title` | Заголовок страницы | `<title>` вкладки браузера + h1 контента |
| `description` | Мета-описание для поисковиков | `<meta name="description">` |
| `headline` | Соц. заголовок для расшаривания | Open Graph `og:title` + Twitter |
| `headimg` | Путь к hero-изображению | `og:image` + featured image WordPress |

### Что если frontmatter отсутствует

- **Нет `title`** → плагин возьмёт **первый `# H1`** из тела как title
- **Нет `description`** → сгенерирует из первых 30 слов контента
- **Нет `headline`** → возьмёт title
- **Нет `headimg`** → возьмёт первое изображение из контента

### Как удалить дубликат h1

Плагин **автоматически удаляет** первый `# H1` из body — потому что в теме h1 уже выводится темплейтом как заголовок страницы (два h1 на странице — плохо для SEO). Так что в файле можно писать h1 — он не будет дублирован.

### Пути к изображениям

- `images/photo.jpg` — относительно `index.md` (рекомендуется)
- `./images/photo.jpg` — так же
- `/absolute/path.jpg` — плагин не поймёт, не используй
- `https://external.com/img.jpg` — плагин **не** загрузит, оставит как внешнюю ссылку

При импорте плагин:
1. Находит все `<img src>` в HTML контента
2. Ищет файл в подпапке `images/` рядом с `index.md`
3. Загружает в медиатеку WP через стандартный `wp_insert_attachment`
4. Заменяет `src` в контенте на URL из медиатеки
5. Если файл не найден — warning в журнал, `<img>` остаётся с оригинальным путём (сломан)

## 6. Специальные шорткоды

Плагин поддерживает **инлайн-шорткоды** внутри `.md` файлов — они автоматически подставляются при импорте или рендере.

### Шорткоды подставляемые при импорте (текст сразу вставляется в контент)

| Шорткод | Что подставляется |
|---|---|
| `$$SITE_NAME$$` | Название сайта (из Настроек WP → Общие → Название сайта) |
| `$$CURRENT_DATE_ISO$$` | ISO 8601 дата импорта (`2026-07-09T14:23:00Z`) — для machine-readable |

### Шорткоды с динамическим рендером (превращаются в WP-шорткод при импорте, рендерятся при показе страницы)

| Шорткод в md | Что становится | Что показывается |
|---|---|---|
| `$$CURRENT_DATE$$` | `[sb_date]` | Дата **последнего изменения** страницы в локали сайта |
| `$$CY$$` | `[sb_year]` | Текущий год (4 цифры) |

**Важно:** динамические шорткоды **автоматически локализуются** под язык сайта. Если WP-админка на русском, а сайт на испанском — дата будет по-испански.

### Расширенные варианты `[sb_date]`

Можно вручную использовать шорткод в `.md` с параметрами:

- `[sb_date]` — дата последнего изменения статьи
- `[sb_date basis="published"]` — дата **публикации** (а не изменения)
- `[sb_date format="j F Y"]` — свой формат (правила PHP `date()`)

Примеры:
```markdown
Актуальность: *Última actualización: $$CURRENT_DATE$$* → «Última actualización: 15 agosto 2026»

Copyright © $$CY$$                                     → «Copyright © 2026»

С момента открытия в [sb_date basis="published" format="Y"] мы...
```

### Шорткод для внутренних ссылок (создаётся автоматически, но можно писать вручную)

**`$$LINK slug | Текст$$`** — умная ссылка (см. раздел 8).

## 7. Блочный синтаксис (17 типов блоков)

Плагин поддерживает **container-block** синтаксис для оформленных блоков. Формат:

```markdown
::: block-name
Содержимое блока (markdown внутри работает)
:::
```

Все 17 доступных блоков разбиты на 4 группы.

### Группа 1: Callout-рамки (цветные плашки с иконками)

| Блок | Когда использовать | Цвет |
|---|---|---|
| `info-callout` | Нейтральная информация, справка | Синий |
| `success-callout` | Позитивный результат, подтверждение | Зелёный |
| `warning-callout` | Предупреждение (не критично) | Оранжевый |
| `danger-callout` | Критический риск | Красный |

Пример:
```markdown
::: warning-callout
**Внимание.** Прогноз действителен только на текущий сезон.
:::
```

### Группа 2: Ключевые выводы и заголовки статьи

| Блок | Что это | Ограничение |
|---|---|---|
| `key-takeaway` | Главный вывод статьи (одна мысль) | без лимита |
| `key-takeaways` | Список ключевых выводов (маркированный) | без лимита |
| `hero-label` | Бейдж-ярлык типа «ЛУЧШИЙ ВЫБОР» | **макс. 1 на страницу** |
| `hero-subtitle` | Подзаголовок под H1 | **макс. 1 на страницу** |

Примеры:
```markdown
::: hero-label
ТОП-ВЫБОР 2026
:::

::: hero-subtitle
Подробный обзор с примерами расчёта и таблицами.
:::

::: key-takeaway
Самое главное — коэффициент выше 1.85 при рисках не выше 25%.
:::

::: key-takeaways
- Первое: сравнение показывает разницу в 12%
- Второе: сезонные факторы влияют на 8% случаев
- Третье: рекомендация — обновлять анализ ежемесячно
:::
```

### Группа 3: Специальные блоки

**`odds-example`** — пример коэффициентов (моноширинный шрифт):
```markdown
::: odds-example
Ставка 100€ × кф 1.85 = 185€ (прибыль 85€)
:::
```

**`glossary-term`** — определение термина:
```markdown
::: glossary-term
### Handicap
Это гандикап, форма ставок где одной команде даётся виртуальная фора...
:::
```

**`details`** — раскрывающийся блок с заголовком (нативный HTML5 `<details>`):
```markdown
::: details Подробнее о правилах
Здесь длинный текст со всеми правилами, который читатель может свернуть.
:::
```

### Группа 4: Блоки с разделителями `---`

Все эти блоки содержат несколько однотипных элементов, разделённых строкой `---`.

**`card-grid`** — сетка из 2–4 карточек:
```markdown
::: card-grid
### Карточка 1
Описание первой.
---
### Карточка 2
Описание второй.
---
### Карточка 3
Описание третьей.
:::
```

**`faq`** — вопросы и ответы (аккордеон):
```markdown
::: faq
## Как рассчитать вероятность?
Ответ на первый вопрос.
---
## Что такое overround?
Ответ на второй вопрос.
:::
```

**`at-a-glance`** (макс. 1 на страницу) — быстрая сводка «метка / значение»:
```markdown
::: at-a-glance
**Рейтинг**
4.5 / 5
---
**Цена**
От €9.99
---
**Лицензия**
MGA / Мальта
:::
```

**`dos-donts`** (макс. 1 на страницу) — две колонки «правильно / неправильно»:
```markdown
::: dos-donts
#### Делай так
- Проверяй лицензию сайта
- Начинай с малых ставок
- Веди учёт результатов
---
#### Не делай так
- Не ставь всё на один матч
- Не гонись за проигрышем
- Не пропускай выходные дни
:::
```

**`worked-example`** — пошаговый пример:
```markdown
::: worked-example
### Шаг 1
Выбери матч из списка сегодняшних.

### Шаг 2
Проанализируй последние 5 игр каждой команды.

### Шаг 3
Рассчитай ожидаемый коэффициент и сравни с букмекером.
:::
```

**`pre-bet-checklist`** — чек-лист с чекбоксами:
```markdown
::: pre-bet-checklist
- [ ] Проверил лицензию оператора
- [ ] Оценил статистику последних 5 матчей
- [ ] Учёл травмы ключевых игроков
- [x] Установил лимит на ставку
:::
```

### Что если блок написан с ошибкой

- **Неизвестное имя блока** (например `::: unknown-name`) → блок остаётся в тексте как есть (визуально сразу видно), в журнал импорта попадает warning с указанием файла
- **Нарушено `max_per_page`** → первый экземпляр рендерится нормально, лишние остаются в тексте + warning в журнал
- **Некорректная внутренняя структура** → блок частично рендерится или пропускается + warning

Импорт **не падает** из-за ошибок в блоках — все проблемы попадают в отчёт.

## 8. Умная перелинковка внутренних ссылок

**Проблема:** статья A содержит ссылку на статью B, но статья B имеет флаг `[DLY]` и опубликуется только через неделю. Обычная ссылка `<a href="/b/">` до этого момента ведёт на 404.

**Решение:** плагин автоматически конвертирует все относительные ссылки в контенте в специальный шорткод, который проверяет статус целевой страницы **при каждом рендере**.

### Как это работает

**При импорте**, плагин находит все относительные ссылки в HTML:

- `<a href="/statistics/nba/">Статистика NBA</a>` → превращается в `$$LINK nba | Статистика NBA$$`
- `<a href="/complex/path/deep-slug/">Ссылка</a>` → `$$LINK deep-slug | Ссылка$$` (берётся последний сегмент)
- `<a href="/articles/foo.html">Тест</a>` → `$$LINK foo | Тест$$` (расширение обрезается)

Внешние ссылки (`http://`, `https://`, `mailto:`, `tel:`, якоря `#`, `//protocol-relative`) **не трогаются**.

**При показе страницы** тема:
- Ищет `$$LINK slug | текст$$` в контенте
- Проверяет slug в кэше опубликованных страниц (транзиент, обновляется каждые 24ч)
- **Если страница опубликована** → рендерит нормальную `<a href="полный-permalink">текст</a>`
- **Если страница НЕ опубликована** (в статусе `future`, `draft`, `trash` или удалена) → рендерит просто «текст» без ссылки

### Автоматическое обновление

Когда DLY-статья наконец публикуется (по расписанию или вручную), кэш slug→permalink **автоматически сбрасывается**:
- при `save_post` — редактирование или создание
- при `future_to_publish` — плановая публикация
- при `deleted_post`, `trashed_post`, `untrashed_post` — удаление

На следующем запросе к любой странице кэш пересобирается, и `$$LINK$$` для новой публикации начинает рендериться как реальная ссылка.

### Что писать в исходном `.md`

Обычные markdown-ссылки — плагин сам всё сконвертирует:

```markdown
Смотри также [Статистика NBA](/statistics/nba/) и [Лучшие игроки](/players/top-10/).
```

### Можно ли писать `$$LINK$$` вручную

Да. Если хочешь принудительно вставить умную ссылку по slug (например в готовом HTML):

```markdown
Читай также $$LINK top-players | список лучших игроков$$.
```

## 9. Импорт FSR-архива — пошаговая инструкция

### Что нужно перед импортом

1. **Сгенерированная и активная тема** (иначе контент будет отображаться в дефолтной теме WordPress). Вкладка **Тема** → «Сгенерировать и активировать»
2. **FSR-архив** — ZIP-файл или папка на сервере с правильной структурой (см. раздел 3)
3. **Свободное место на диске** — файлы медиатеки, кэши, база

### Шаг 1: подготовка

Вкладка **FSR Import** содержит две панели:
- **Загрузка архива** — можно загрузить ZIP (до 100 МБ) или указать путь на сервере
- **Настройки импорта** — режим публикации DLY, размер batch'а

### Шаг 2: маппинг полей

После загрузки архива плагин показывает **маппинг frontmatter → WordPress meta**:

| YAML-поле в index.md | WordPress meta-ключ |
|---|---|
| `title` | `post_title` |
| `description` | `_custom_seo_desc` |
| `headline` | `_custom_seo_headline` (для Open Graph) |
| `headimg` | `_thumbnail_id` (featured image) + `fsr_headimg` (путь) |

Можно **переопределить** маппинг — если файлы используют другие имена полей. Настройки сохраняются в опции `fsr_get_mapping` / `fsr_save_mapping`.

### Шаг 3: режим публикации DLY

Три режима (см. раздел 11):
- **Instant** — публиковать всё сразу
- **One day** — по одной DLY-странице в день
- **Period** — растянуть все DLY-страницы равномерно на N дней

Плюс дополнительная опция «Прогрев» (waiting week) — добавить +7 дней ко всем датам публикации, чтобы новый сайт не выглядел подозрительно.

### Шаг 4: запуск

Кнопка «Начать импорт» → плагин:
1. Сканирует архив, собирает очередь задач
2. Показывает прогресс-бар и логи в реальном времени
3. Обрабатывает батчами (~15 страниц за AJAX-запрос — настраивается)
4. По завершении — редирект на вкладку **Отчёт**

### Что произойдёт с существующими страницами

Плагин **не удаляет** существующие страницы автоматически. Если ты импортируешь второй раз тот же архив:
- Плагин сравнит хэши файлов через meta `_sb_file_hash`
- Если хэш совпадает → страница пропускается (nothing to update)
- Если хэш изменился → страница **обновляется** (post_content, meta) с сохранением ID и slug
- Если папка удалена из архива → **осиротевшая страница остаётся** — надо удалить вручную или через **Откат**

### Прерывание импорта

Кнопка «Остановить» — приостанавливает обработку. Незавершённые задачи остаются в опции `site_builder_active_import` и можно продолжить (кнопка «Продолжить») или сбросить (кнопка «Очистить состояние»).

Если браузер закрылся посреди импорта — обычно можно продолжить с того же места после перезагрузки страницы.

## 10. Настройка темы (Header / Footer / Style)

Вкладка **Тема** — конструктор WordPress-темы из выбранных вариаций.

### Три категории

Каждая тема состоит из трёх компонентов:

1. **Header (шапка)** — сейчас доступно **8 вариантов**: `classic`, `minimal`, `modern`, `sticky-slim`, `off-canvas`, `two-row`, `accent-topbar`, `bordered-boxed`, `mega-menu`, `pill-nav`, `underline-tabs` (список расширяется)
2. **Footer (подвал)** — **9 вариантов**: `classic`, `columns`, `simple`, `rich-4col`, `newsletter-highlight`, `modern-divided`, `brand-statement`, `card-columns`, `cta-band`, `minimal-3`, `seo-columns`
3. **Style (цветовая схема)** — **11 вариантов**: `bright`, `dark`, `elegant`, `corporate-navy`, `neon-glow`, `warm-earth`, `bold-crimson`, `fresh-mint`, `graphite-mono`, `ocean-breeze`, `royal-purple`

### Как выбрать

- Каждая категория показана горизонтальным рядом карточек
- **Свайп** или **стрелки** для навигации
- **Активный** вариант выделен голубой рамкой + ✓ в углу
- Для стилей — показан **превью-палитра** с 4-5 цветами (так сразу видно как будет)

### Кнопка «Сгенерировать и активировать тему»

При нажатии плагин:
1. Копирует базовые файлы темы (functions.php, index.php, page.php и т.д.) в `wp-content/themes/site-builder-theme/`
2. Собирает `style.css` из выбранного стиля + CSS выбранного header + CSS выбранного footer
3. Копирует PHP шаблоны header и footer как `header.php` и `footer.php`
4. Если у каких-то вариаций есть `.js` — собирает единый `assets/theme.js` в теме
5. Активирует тему (если не активна)

### Что произойдёт с ручными правками темы

**Ничего хорошего.** Тема **перезаписывается** при каждой генерации. Если ты руками правил `wp-content/themes/site-builder-theme/style.css` — при следующей генерации правки пропадут.

**Правильный путь:** менять исходные файлы плагина в `templates/theme/` — они переживут любое количество перегенераций.

### Дополнительные элементы (чекбоксы)

Внизу вкладки — секция «Дополнительные элементы» с чекбоксами, которые **работают мгновенно** (не требуют перегенерации темы):

- **Хлебные крошки** — выводить цепочку «Главная → предки → текущая» перед заголовком страницы. На главной не показываются никогда.

Настройки хранятся в опции `site_builder_theme_module_options`.

## 11. DLY — отложенная публикация статей

### Три сценария распознавания в имени папки

| В имени папки | Что происходит |
|---|---|
| **Нет флага DLY** | Публикуется сразу (обычный случай) |
| **`[DLY]`** без даты | Идёт в «расписание импорта» — распределяется по датам |
| **`[DLY=YYYY-MM-DD]`** с датой | Публикуется ровно в этот день на **рандомное время 9:00–22:00** |

### Три режима расписания (в UI FSR Import)

| Режим | Что делает | Применяется к |
|---|---|---|
| **Instant** | Публиковать всё сразу | `[DLY]` без даты — публикуется немедленно. **`[DLY=дата]` продолжает работать** |
| **One day** | По одной странице в день | 1-й DLY — через 1 день, 2-й — через 2 дня, и т.д. |
| **Period** | Растянуть на N дней | Все `[DLY]`-страницы равномерно на N дней |

**Плюс опция «Прогрев»** (waiting week) — при выборе `one_day` или `period` появляется чекбокс. Если включён — добавляет +7 дней ко всем DLY-датам (чтобы новый сайт не выглядел так, будто в первый день сразу опубликовал 40 статей).

### Рандомизация времени суток

Все DLY-статьи публикуются в **9:00–22:00** локального времени сервера, а не в 00:00 (это был бы очевидный признак автоматизации).

- **Детерминированно** — тот же `dly_seq` при повторном импорте даёт то же время. Если сделаешь rollback и повторный импорт — времена совпадут.
- Работает и для `[DLY]` без даты, и для `[DLY=YYYY-MM-DD]` с явной датой (там рандомизируется только время суток, дата фиксирована)

### Как WordPress публикует запланированные посты

WordPress использует **wp-cron** — механизм срабатывающий при каждом заходе на сайт. Если сайт мало посещается, публикация может задержаться.

**Правильный путь для продакшена**: настроить настоящий `cron` на сервере, чтобы отключить wp-cron и запускать вручную:
- В `wp-config.php` добавить: `define('DISABLE_WP_CRON', true);`
- В сервере: `*/5 * * * * wget -q -O - https://mysite.com/wp-cron.php?doing_wp_cron`

Иначе первый посетитель после запланированного времени «оплачивает» задержку.

## 12. SEO — как это работает

### Как плагин генерирует SEO-разметку

Модуль `inc/seo.php` темы генерирует три группы тегов при выводе каждой страницы:

**1. Стандартные мета-теги:**
- `<title>` — из frontmatter `title` или `_custom_seo_title` meta
- `<meta name="description">` — из `description` или `_custom_seo_desc` meta
- Canonical URL, robots meta

**2. Open Graph** (для расшаривания в соцсетях):
- `og:title` (headline или title)
- `og:description`
- `og:image` (headimg)
- `og:type` (`article` для статей, `website` для главной)
- `og:url`

**3. Twitter Cards** — те же данные в формате Twitter.

**4. JSON-LD Schema.org** — микроразметка для поисковиков:
- `Article` для обычных статей
- `WebPage` для utility страниц (`[U]`)
- `CollectionPage` для articles-grid страниц (`[A]`)

### Приоритеты источников для SEO-полей

Плагин ищет данные в таком порядке (fallback chain):

1. **`_custom_seo_*`** meta — ручная правка через админку WP (высший приоритет)
2. **`fsr_*`** meta — данные из frontmatter FSR-архива
3. **`post_title` / `post_excerpt`** — стандартные поля WP

Значит:
- Если после импорта редактор правит SEO через админку → приоритет у ручной правки
- При переимпорте плагин **не перезаписывает** ручные правки

### Автодетект чужих SEO-плагинов

Модуль `seo.php` **автоматически проверяет** наличие популярных SEO-плагинов:

- Yoast SEO
- RankMath
- All in One SEO Pack
- SEOPress

**Если они установлены и активны** → наш модуль **отключает свою SEO-разметку**, чтобы не конфликтовать. Плагины Yoast/RankMath более функциональные и должны победить.

### Что попадает в sitemap

Автоматически создаётся страница **Sitemap** (slug `/sitemap/`) — это HTML-карта сайта (не XML). Она показывает:
- Все опубликованные страницы иерархически
- Использует accordion (нативный `<details>`) для больших разделов
- Локализованные названия («Sitemap», «Карта сайта», «Mapa del sitio»)

### Хлебные крошки

Если включены в UI (Тема → Дополнительные элементы → Хлебные крошки):
- Показываются **перед h1** на всех страницах кроме главной
- Формат: `Главная → предок → предок → текущая страница`
- Локализованы (36 языков)
- Включают schema.org `BreadcrumbList` разметку

## 14. Прочие вкладки: MD Restore, Отчёт, Откат, Настройки

### MD Restore

Служит для **восстановления оригинального контента** страниц из бэкапа `.md` файла.

**Сценарий:** редактор внёс правки в статью через WP-админку, но результат оказался хуже оригинала. Можно вернуть исходный markdown.

- Плагин при импорте сохраняет **оригинальный markdown** в meta `_sb_original_md` каждой страницы
- Вкладка **MD Restore** показывает список страниц, для которых доступен бэкап
- Выбор страницы → кнопка «Восстановить» → плагин перезаписывает `post_content` из бэкапа

**Осторожно:** восстановление **необратимо** без нового бэкапа. Правки редактора будут потеряны.

### Отчёт

**Журнал импорта** — все действия плагина за последние импорты.

Показывает:
- **Стек импортов** — каждый запуск как отдельная сессия с датой/временем
- **По каждой странице** — успех / ошибка / warning
- **Warnings** — блоки не распознались, ссылки не резолвятся, лимит превышен, missing images и т.д.
- **Errors** — что-то упало на импорте (index.md пустой, ошибка записи в БД)
- **Статистика** — сколько страниц обработано, сколько картинок загружено

**Логика хранения**: журнал хранится в таблице `wp_sb_import_journal`, автоматически чистится (сохраняются последние 10 импортов).

### Откат

**Откат всего импорта** — удаление всех страниц, картинок и меню, созданных плагином.

- Выбор импорта из журнала → кнопка «Откатить»
- Плагин находит все страницы с meta `_sb_import_id = X` → удаляет
- Соответствующие attachments в медиатеке — тоже удаляются
- Меню-элементы — восстанавливаются в изначальном виде

**Осторожно:** откат **удаляет** все ручные правки редактора если они были сделаны на этих страницах. Используй когда хочешь начать с чистого листа.

**Есть режим soft delete** — страницы переводятся в trash вместо hard delete. Так можно быстро восстановить если что.

### Настройки

**Размер batch'а** — сколько страниц обрабатывать за один AJAX-запрос:

| Параметр | По умолчанию | Комментарий |
|---|---|---|
| **FSR-импорт** | 15 | Основной поток. Уменьши если PHP timeout срывает импорт |
| **Legacy CREATE** | 10 | Для старых MJ-архивов |
| **Legacy ADD** (с папками картинок) | 5 | Меньший — так как много I/O на изображения |

**Правила подбора:**
- Слабый сервер / медленный диск → уменьши до 5-8
- Мощный сервер / SSD / много RAM → можно увеличить до 25-30
- Если срываются PHP timeout (обычно 30 секунд) → **срочно уменьшить**

**Шаблоны страниц Sitemap и Articles Grid** — можно переопределить slug и заголовок автоматически создаваемых страниц:
- Slug: `sitemap`, заголовок: «Sitemap» (локализовано)
- Slug: `articles`, заголовок: «Все статьи»

### Экспериментальные функции

В настройках есть **DANGER ZONE** — сброс всего плагина к состоянию первой установки. Стирает опции, journal, но **не трогает страницы**. Используй только если плагин совсем сломался и нужен fresh start.

## 15. Типичные ошибки и как их лечить

### «Импорт не запускается, кнопка не работает»
- **Проверь** что тема сгенерирована (Тема → «Сгенерировать и активировать»)
- **Проверь** консоль браузера (F12) — если ошибка `403 Forbidden` в AJAX, то WordPress nonce истёк. Обнови страницу
- **Проверь** права пользователя — надо `manage_options`

### «После импорта страницы пустые, только h1»
- Скорее всего в `index.md` есть **нестандартный markdown** (например `[[...]]` викиссылки), который наш парсер не понял → всё после первого нестандартного элемента съедено. Открой файл, посмотри
- **Второй сценарий**: HTML-контент в `index.md` (не markdown) без нужного парсера. Плагин поддерживает `.html` и `.md` — но для `.html` нужен `<body>` или `<main>` tag

### «Импорт зависает на 30-50%»
- **PHP timeout** — уменьши размер batch'а в **Настройки → FSR-импорт**. Попробуй 5-8 вместо 15
- **Memory limit** — увеличь `memory_limit` в `wp-config.php`: `ini_set('memory_limit', '512M')`
- **Проверь логи сервера** — обычно там понятная ошибка

### «Картинки не загрузились (broken img)»
- Причина: файл в `<img src="images/photo.jpg">` не найден в `images/` рядом с `index.md`
- **Проверь** структуру архива, регистр букв (Linux чувствителен)
- Плагин пишет warning в **Отчёт** — там указан конкретный файл

### «Ссылки на другие статьи ведут на 404»
- Скорее всего целевая страница ещё **не опубликована** (DLY-статья в статусе future) — тогда ссылка должна быть текстом. Если ведёт на 404 — значит **шорткод $$LINK не отработал**
- **Проверь**: работает ли тема (модуль `link-resolver.php` должен быть в теме). Пересобери тему в **Тема → «Сгенерировать»**
- **Проверь**: правильно ли slug целевой страницы. WP может добавить `-2` если slug дублируется

### «На испанском сайте кнопки/тексты остались на русском»
- **Проверь** язык сайта: Настройки → Общие → Язык сайта. Должен быть `es_ES` (Español (España)), а не только язык админки
- Если стоит `es_ES` а тексты всё равно английские — пересобери тему (обновлённый `i18n.php` попадёт в тему)

### «Дата в статьях показывается на русском на не-русском сайте»
- **Проверь** язык сайта (не язык админки)
- Обычно старые статьи которые импортировались до 1.1.3-beta2 имеют дату **захардкоженную текстом**. Такие статьи нужно **переимпортировать** — плагин заменит на shortcode `[sb_date]`

### «При импорте два раза одну и ту же папку получил дубли страниц»
- Плагин определяет уже существующие страницы по **slug**. Если между импортами slug изменился — плагин не увидит связь и создаст дубль
- **Решение**: воспользоваться **Откатом** первого импорта, потом второй импорт

### «После активации плагина главная страница пустая»
- Плагин при активации создаёт страницу «Все статьи», но не назначает её главной. Главная — то что в Настройки → Чтение → «Отображается на главной странице»
- **Решение**: главная страница WordPress берётся из **корневого `index.md`** архива автоматически (плагин выставляет `page_on_front` при импорте). Если контент главной не появляется — проверь что в корне архива есть `index.md`. Можно также вручную назначить любую страницу как главную в Настройки → Чтение

### «PHP fatal error после обновления плагина»
- Скорее всего конфликт версий. Плагин сохраняет `site_builder_version` в опциях и запускает миграции автоматически. Если миграция не сработала:
- **Отключи** плагин, **обнови** до нужной версии, **включи** заново — запустит миграцию заново

### «Не могу переключить тему обратно на дефолтную»
- Плагин делает бэкап старой темы в опции `site_builder_pristine_theme_files`
- В Настройки → Внешний вид → Темы — переключи на любую другую (Twenty Twenty-Four, например). Тема site-builder-theme останется в списке
- Если хочешь **удалить** тему site-builder-theme — сначала переключись, потом кнопка «Удалить» в WP

## Приложение: краткая справка (Cheat Sheet)

### Флаги в именах папок

```
[M] [1M] [M3] [2M3;Метка]       ← главное меню
[F] [1F] [3F;Метка]              ← футер-меню
[U]  utility (privacy, legal)
[A]  articles grid
[W]  метка «Страница О нас» (обычно с [U])
[N]  news category
[E]  events category
[DLY]  отложенная публикация
[DLY=2026-08-15]  публикация в конкретный день
```

### Шорткоды в контенте

```
$$SITE_NAME$$        → "Мой сайт"
$$CURRENT_DATE$$     → [sb_date] → "15 августа 2026" (динамически)
$$CY$$               → [sb_year] → "2026" (динамически)
$$CURRENT_DATE_ISO$$ → "2026-07-09T14:23:00Z"
$$LINK slug | text$$ → умная ссылка
```

### Блоки

```
::: info-callout / success-callout / warning-callout / danger-callout
::: key-takeaway / key-takeaways
::: hero-label / hero-subtitle       (макс. 1 на страницу)
::: odds-example
::: glossary-term
::: details Заголовок
::: card-grid                        (карточки через ---)
::: faq                              (Q/A через ---)
::: at-a-glance                      (метки/значения через ---, макс. 1)
::: dos-donts                        (два блока через ---, макс. 1)
::: worked-example                   (шаги через ### Шаг N)
::: pre-bet-checklist                (- [ ] / - [x])
```

### Frontmatter YAML

```yaml
---
title: Заголовок страницы
description: SEO-описание (150-160 символов)
headline: Соц. заголовок для расшаривания
headimg: images/hero.jpg
---
```

### Функция в шаблонах темы

```php
sb_t('home')                          → локализованный текст
[sb_date]                             → дата модификации в локали
[sb_year]                             → текущий год
sb_link_get_slug_map()                → карта slug→URL опубликованных
```
