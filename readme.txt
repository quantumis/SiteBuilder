Внутренний инструмент массового импорта контента в WordPress.

== Description ==

Site Builder — это плагин для автоматического развертывания WordPress-сайтов из подготовленных архивов контента. Поддерживает два режима:

* **Создание сайта** — полный импорт сайта с нуля, включая главную страницу, подвал, стили и структуру вложенных страниц.
* **Добавление страниц** — расширение уже работающего сайта дополнительными статьями.

В обоих режимах поддерживается отложенная публикация: можно опубликовать всё сразу, по странице в день, либо растянуть публикации на заданный период.

Любой импорт можно полностью откатить — плагин хранит точку отката последнего запуска.

== Installation ==

1. В админке WordPress откройте «Плагины → Добавить новый → Загрузить плагин».
2. Выберите ZIP-файл плагина и нажмите «Установить сейчас».
3. После установки нажмите «Активировать».
4. В сайдбаре админки появится пункт меню «Site Builder».

== Changelog ==

= 1.0.0-beta1 =
* **Этап Б подготовки к 1.0.0 — флаги и меню.**
* **Меню `[M]` — Main Auto Menu.** Каждая страница с флагом `[M]` теперь добавляется в основное меню сайта (`Main Auto Menu`). Поддержаны все опции грамматики флага: `order` (порядок), `depth` (глубина раскрытия подменю — сохраняется в `fsr_menu_depth` для использования темой), `label` (текст пункта меню вместо slug). Если родительская страница в URL-структуре тоже имеет `[M]`, дочерний пункт становится её подпунктом — иерархия страниц превращается в иерархию подменю.
* **Меню `[F]` — Footer Auto Menu.** Аналогично для футера: страницы с `[F]` идут в новое меню `Footer Auto Menu` с опциями `order` и `label`.
* **Поведенческие флаги через post_meta.** Каждый из одно-буквенных флагов сохраняется как отдельный post_meta для лёгкого использования темой:
  * `[U]` → `fsr_utility = 1` (техническая страница, отключение рекламы)
  * `[A]` → `fsr_articles_grid = 1` (рендер карточек дочерних статей с пагинацией)
  * `[W]` → `fsr_about = 1` (страница «О нас»)
  * `[N]` → `fsr_news_page = 1` (страница новостей)
  * `[E]` → `fsr_events_page = 1` (страница матчей/событий)
  * Ключи без подчёркивания → видны в Custom Fields. Всегда записываются как 0 или 1 (а не отсутствуют для false) — тема может читать через `get_post_meta($id, 'fsr_utility', true)` без проверки существования.
* **Откат меню.** Каждый созданный пункт меню и оба меню целиком трекаются в журнале импорта. Откат корректно удаляет пункты и сами меню.

= 1.0.0-alpha4 =
* **Фикс: интерфейс маппинга полей не отображал содержимое.** В подсказках слотов «SEO Title» и «H1 Title» использовались литералы `<title>` и `<h1>` без HTML-экранирования. Браузер интерпретировал их как настоящие теги — открывал реальный `<title>`-элемент, и весь остальной HTML страницы оказывался в нерендерящемся `<head>`-контексте. Заменил на HTML-entities (`&lt;title&gt;`, `&lt;h1&gt;`).

= 1.0.0-alpha3 =
* **Фикс: маппинг полей работает на свежем сайте.** Раньше список доступных `meta_key` строился только из тех ключей, которые уже есть в `wp_postmeta` — на чистом сайте без страниц и SEO-плагинов это давало пустой список, и пользователь не мог ничего выбрать. Теперь список всегда содержит расширенный набор известных ключей популярных SEO-плагинов (Yoast, Rank Math, AIOSEO в старой и новой версиях, Genesis, SEOPress, Squirrly) даже если они ещё не установлены — плагин просто создаст эти `meta_key` при первом импорте. Ключи помечаются бейджами «есть в БД» / «будет создано» / «свой».
* По умолчанию (когда пользователь ещё не сохранял маппинг) предзаполнены Yoast + Rank Math — это самые популярные плагины и в большинстве случаев пользователь хочет писать в оба. Если ни один не установлен — `meta_key` просто создадутся.
* Добавлена возможность ввести **произвольный `meta_key`** для каждого слота — input «Свой meta_key» внизу строки. Полезно для кастомных тем с нестандартными именами полей. Валидация: латинские буквы, цифры, `_`, `-`, `:`.

= 1.0.0-alpha2 =
* **Фикс: главная страница теперь показывает контент.** Тема `minipages` (и любая другая с собственным `front-page.php`) не вызывает `the_content()` для главной — WordPress использует `front-page.php` напрямую, минуя стандартный шаблон страницы. Теперь FSR-импорт корневой страницы дополнительно встраивает её HTML в маркер `<!-- Enter Code -->` файла темы `front-page.php` (та же логика, что уже работает в режиме CREATE). Файл темы получает pristine-snapshot, откат корректно восстанавливает оригинал.
* **Маппинг SEO-полей.** Перед запуском импорта пользователь проходит шаг «Маппинг полей»: для каждого из 5 фиксированных слотов FSR-формата (SEO Title, Meta Description, Social Headline, OG Description, H1 Title) выбирает, в какие `meta_key` сайта это значение должно записаться. Авто-предложения для Yoast, Rank Math, AIOSEO, Meta Title, Headline и других популярных названий. Чекбокс «показать приватные» открывает поля с префиксом `_`. Маппинг сохраняется и переиспользуется при следующих импортах. Раньше плагин жёстко писал в Yoast+Rank Math одновременно, что не подходило для пользователей с другими SEO-плагинами или с темой, использующей кастомные поля.
* **Custom Fields visibility.** Поля флагов FSR теперь сохраняются без подчёркивания в начале (`fsr_flags` вместо `_fsr_flags`, аналогично `fsr_headline`, `fsr_headimg`). WordPress скрывает meta-поля с префиксом `_` в стандартной панели Custom Fields редактора страницы — теперь они видны и могут быть просмотрены вручную.

* Откат FSR-импорта работает через стандартный механизм плагина: страницы удаляются, опции `show_on_front`/`page_on_front` восстанавливаются.

= 0.7.4aus2 =
* Корневая MD-страница теперь правильно становится главной страницей сайта (URL `/`), а не `/home/`. Технически: корневая страница создаётся с `post_parent = 0` и назначается через стандартные опции WordPress `show_on_front = 'page'` + `page_on_front = <id корневой>`. Все top-level страницы (раньше дети `/home/`) тоже теперь имеют `post_parent = 0` — значит их URL становятся `/online-casinos/`, `/about/`, и т.д. без лишнего `/home/` префикса. Дети сохраняют свою иерархию: `/online-casinos/5-gringos-casino/` остаётся вложенной правильно.
* Старые опции `show_on_front` и `page_on_front` сохраняются в snapshot перед изменением — откат восстановит их прежние значения (как уже делает CREATE-режим).

= 0.7.4aus =
* Отдельная ветка для срочного восстановления сайтов из .md-снимков. Добавлен режим **MD Restore** — третий рядом с CREATE и ADD.
* Новая вкладка «MD Restore»: сканирует папку с .md-файлами, парсит шапку каждого (`# URL:`, `# Title:`, `# Description:`), восстанавливает иерархию страниц по URL (`/a/b/c` → парент = страница `b` под `a`), конвертирует FAQ-блоки `[ Вопрос ](#) Ответ` в шорткод `[faq][id="N" title="..." desc="..."][/faq]`, преобразует markdown в HTML (заголовки H2-H6, списки, **bold**, [ссылки], таблицы), создаёт страницы и пишет SEO-мета одновременно в Yoast и Rank Math.
* MD Restore не трогает тему, не создаёт меню, не работает с картинками — это быстрый режим восстановления текстового контента.
* Если в архиве отсутствует промежуточная родительская страница (например, есть `/online-casinos/casino-x`, но нет `/online-casinos/` как отдельного файла), плагин автоматически создаёт пустую страницу-заглушку — иначе при отсутствии родителя терялись бы целые ветки. Заголовок заглушки формируется из slug. После импорта эти заглушки можно либо наполнить контентом вручную, либо удалить через стандартную админку.
* Откат и Отчёт расширены — теперь поддерживают тип `md_restore` наравне с CREATE и ADD.
* Все правки изолированы в новых файлах (`class-md-restore.php`, `views/tab-md.php`) и нескольких местах с дописанным кодом. CREATE и ADD не затронуты.

= 0.7.4 =
* Полностью переработана логика извлечения контента из HTML-страниц, чтобы покрыть все варианты вёрстки, которые присылает контентная команда. Раньше плагин выбирал один контейнер (`<main>` или `<article>`), и в зависимости от того, где в конкретном архиве лежала вступительная картинка (hero), она могла теряться. Теперь применяется вычитающий подход: берётся всё тело страницы (`<body>`), затем удаляются служебные блоки — вся навигация (`<nav>`), подвалы (`<footer>`) и «шапка сайта» (`<header>` без заголовка `<h1>` — то есть логотип и меню). Заголовок статьи, вступление и hero-картинка сохраняются независимо от того, в каком контейнере они лежат. Старые архивы-фрагменты (без `<body>`) проходят без изменений.
* Побочный плюс: из импортируемого контента теперь надёжно вырезаются навигационные меню и «хлебные крошки» архива — WordPress-тема рисует свои.

= 0.7.3 =
* Исправлено исчезновение hero-картинок на страницах нового формата, в котором `<header>` со вступительной картинкой лежит ВНУТРИ `<article>`, но СНАРУЖИ `<main>`. Раньше плагин брал только содержимое `<main>` и тем самым выбрасывал заголовок и hero-картинку. Теперь приоритет такой: 1) единственный `<article>` (захватывает header с hero), 2) `<main>`, 3) `<body>`. Если на странице несколько `<article>` (listing-page), используется `<main>` — как раньше.
* Бонус: на архивах формата как hraciautomaty (где `<article>` внутри `<main>`) из импорта теперь удаляются «чужие» хлебные крошки, которые лежали внутри `<main>` рядом с `<article>` — тема WordPress всё равно рисует свои.

= 0.7.2 =
* Исправлен поиск картинок, когда в HTML указан путь без префикса `images/`. В новых архивах от контентной команды иногда встречается формат `<img src="hero.webp">` вместо привычного `<img src="images/hero.webp">`, хотя сам файл лежит в подпапке `images/`. Раньше плагин не находил такие файлы — ни одна картинка страницы не загружалась. Теперь плагин ищет в трёх местах: 1) путь как написано, 2) `images/{имя файла}` рядом с HTML, 3) `hub/images/` (общая медиатека сайта).

= 0.7.1 =
* Удаление обёртки вокруг миниатюрной картинки. Раньше, когда первая картинка извлекалась как миниатюра страницы, её обёртка (`<figure class="hero">`, `<div class="hero-image">` и подобные) оставалась пустой и могла давать на сайте лишние отступы/рамки. Теперь обёртка удаляется целиком вместе с картинкой. Удаление безопасное: `<figure>`, `<picture>` и ссылки-обёртки `<a>` удаляются всегда; `<div>`/`<section>`/`<span>` — только если в классе есть подсказка (`hero`, `image`, `media`, `featured`, `thumb`, `banner`, `cover`, `illustration`) И внутри нет другого содержимого, кроме картинки. Если родитель не похож на обёртку — удаляется только сам `<img>`, как раньше.

= 0.7.0 =
* Поддержка нового формата архивов от контентной команды. Три изменения работают автоматически, без UI-переключателей.
* **`<main>`-экстракция**: если HTML-файл страницы — это полная страница с своим `<head>`, `<header>`, `<footer>` (новый формат), плагин теперь извлекает только содержимое `<main>`. Раньше всё это вставлялось в WordPress-страницу целиком и получалась «страница в странице» (двойные мета-теги, двойные навигации). Для старых архивов-фрагментов (без `<main>`) поведение не меняется — приоритет: `<main>` → `<body>` → весь HTML.
* **`index*.html`**: плагин теперь подхватывает файлы с именами `index2.html`, `index22.html` и подобными. Приоритет: `index.html` (точное совпадение) → `index*.html` (любой) → первый `.html` в папке.
* **Автопоиск «реального корня» архива**: если архив завёрнут в одну или несколько папок-обёрток (например, `archive/inner1/domain.com/<реальный контент>`), плагин сам спускается через обёртки. Условие: на пути должна быть ровно одна значимая подпапка. Признак реального корня: есть `hub/` (для CREATE) или папка содержит HTML/имеет подпапки с HTML (для ADD). Максимум 5 уровней спуска. Старые архивы, лежащие в правильной структуре, не затрагиваются — углубление пропускается.
* Рабочие файлы редакторов (`canonical-sources.md`, `linking-map.docx`, `master-fact-registry.md` и подобные `.md`/`.docx`) больше не мешают сканированию — они не папки, поэтому естественно игнорируются логикой сканера.
* Миниатюра страницы теперь берётся из первой картинки внутри `<main>`, а не из всего HTML — это исправляет ситуацию, когда логотип сайта из `<header>` мог стать миниатюрой страницы.

= 0.4.0 =
* Этап 4: вкладка «Откат» теперь рабочая.
* Откатывается последний завершённый импорт (CREATE или ADD) одним кликом: удаляются созданные страницы и картинки, восстанавливаются изменённые файлы темы (`front-page.php`, `footer.php`), восстанавливаются опции главной страницы, удаляются добавленные пункты меню, удаляется само меню (если оно создавалось этим импортом).

* Исправлен баг: в версии 0.3.2 импорт всё равно прерывался, даже если пользователь в диалоге «Покинуть страницу?» нажимал «Отмена». Причина — отправка отмены из обработчика `beforeunload`, который не знает, согласится ли пользователь покинуть страницу. Теперь отмена отправляется только из событий `pagehide` / `unload`, которые срабатывают исключительно при фактическом уходе со страницы.

= 0.3.2 =
* Защита от потери импорта при переключении вкладок и перезагрузке страницы: пока импорт идёт, любая попытка уйти со страницы (клик по другой вкладке плагина, обновление страницы, закрытие) показывает подтверждение, и в случае согласия пользователя текущий импорт корректно отменяется (через `navigator.sendBeacon`).
* Карточка «Активный импорт» в шапке страницы плагина показывает данные текущего активного импорта, прогресс и кнопку «Прервать и сбросить». Это позволяет вручную разблокировать застрявший импорт (вместо ожидания 5 минут до автоматического протухания heartbeat).
* Если на сервере есть запись об активном импорте — обе формы запуска (CREATE и ADD) блокируются на UI до сброса блокировки.
* Подсказка пользователю: если последний heartbeat был более 30 секунд назад, карточка активного импорта подсвечивается жёлтым и сообщает, что импорт, скорее всего, прерван и его можно сбросить.

Кнопка по умолчанию `disabled` в HTML, но JS не активировал её в случае, когда подтверждение «УДАЛИТЬ» не требовалось. Проблема проявлялась после полной очистки сайта (например, через WP Reset).

= 0.2.3 =
* Новый чекбокс «Ждать 1 неделю перед публикацией отложенных страниц» на вкладке «Создание сайта». Если включён, все отложенные публикации (то, что выходит не мгновенно) сдвигаются на 7 дней вперёд. Полезно для SEO-«прогрева» сайта первыми страницами. Чекбокс не показывается в режиме «Опубликовать всё сразу».

= 0.2.2 =
* Исправлен критический баг с миниатюрами страниц: при дедупликации картинок плагин ориентировался на имя файла, а не на его содержимое. В типичных архивах каждая страница имеет свой `hero.webp`, но плагин загружал только первый встретившийся и подставлял его как миниатюру всем последующим страницам. Теперь дедупликация идёт по md5-хэшу содержимого: реально одинаковые картинки переиспользуются, разные — загружаются отдельно (WordPress сам делает имена файлов уникальными).
* Главная страница теперь получает миниатюру из первой картинки HUB-индекса — раньше она оставалась без миниатюры.

= 0.2.1 =
* Исправлен баг иерархии страниц: если в hub/images лежала картинка с именем, совпадающим со слагом страницы (например `kryptomeny.webp` для страницы `kryptomeny`), WordPress переименовывал страницу в `kryptomeny-2`, что ломало вложенность дочерних страниц и хлебные крошки. Теперь страницы получают свой слаг приоритетно перед attachment-конфликтом.
* UI: поле «Вложенных страниц сразу» автоматически скрывается в режиме «Опубликовать всё сразу», где оно не применяется.
